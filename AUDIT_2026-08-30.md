## Defects fixed

### Data integrity and security

- Prevented two verification workers from overwriting each other's stored
  evidence or returning a misleading conflict after another worker committed a
  valid decision.
- Prevented automatic payout when a concurrent verification result has already
  raised review flags.
- Kept payout, wallet credit, and review decisions transactionally guarded and
  idempotent.
- Hardened API body parsing and upload limits so malformed or oversized input
  produces safe, useful responses without leaking request contents.
- Aligned rejection-reason validation and server/client limits.

### Reachability and performance

- Added honest, growing pagination to buyer orders so an older delivered order
  can always be reached and confirmed; this closes a path where earned points
  could otherwise remain inaccessible.
- Added growing reads/lazy rendering to seller orders, seller listings, and
  wallet history instead of silently hiding older records.
- Made capped administrator queues and counts explicitly report partial totals.
- Replaced eager queue/list rendering with lazy rendering where it could cause
  startup stalls or excessive image/network work.

### UI, accessibility, and recovery

- Improved responsive layouts, large-text behavior, loading/error states,
  retry actions, in-progress feedback, and empty states across administrator,
  seller, wallet, donation, and account screens.
- Added unsaved-change protection to forms and corrected a false dirty-state
  prompt after a denied location lookup.
- Disabled suspended sellers' listing edit entry points consistently.
- Made short/empty wallet history pull-to-refreshable.
- Added a useful seller-sales empty state with a direct route to listings.
- Moved notification permission into contextual UI, added settings recovery,
  and rechecks permission when the app resumes without rewriting an unchanged
  device record on every resume.
- Improved media upload validation, compression/privacy handling, conflict
  recovery, and save/navigation behavior in the product editor.
- Confirmed the refreshed sign-in experience is clear and unclipped at desktop
  and phone sizes.

## Firestore rules audit

The rules audit found no remaining privilege-escalation, ownership-bypass,
balance-write, create/update asymmetry, or unbounded-list issue in the reviewed
paths. The rules deny access by default, keep wallet balances server-owned,
validate bounded document shapes, and enforce role/ownership checks. All rule
tests and the deployment compiler dry run passed.

## Release note

The new composite indexes in `firestore.indexes.json` passed the deployment dry
run but have not been deployed. Include the Firestore indexes in the next normal
release before relying on the updated administrator completed-work queries in
production.

Before a store release, perform one staging-device pass for camera, location,
notification-permission, and background/resume behavior. Those native OS flows
cannot be fully represented by the web browser smoke test, although their app
logic is covered by the automated suite.
